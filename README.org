* delator

delator is a tracing library for OCaml 5.2 and OxCaml. It is being built for
the developers of vērōcaml, where understanding how a value moved through a
compiler lowering pipeline is often more useful than a large amount of
ordinary logging.

delator provides nested spans, structured fields, target filters, domain-local
buffering, and PPX function instrumentation. Log levels may be removed by the
PPX before the OCaml compiler sees them.

** Status

delator is young and its first consumer is still being developed alongside it.
The runtime and PPX are tested against OxCaml ~5.2.0+ox~ and ppxlib
~0.33.0+ox~. A stock OCaml build is also kept working, but OxCaml is the primary
target and is where the performance-sensitive implementation is tested.

** Install

From a checkout:

#+BEGIN_SRC sh

opam install .

#+END_SRC

Applications add ~delator~ to their libraries and ~delator.ppx~ to their PPX
pipeline. The package requires OCaml 5.2 or newer, dune 3.17 or newer, and
ppxlib 0.33 or newer.

** Design

*** Compile-Time Log Levels

A statically disabled log expands to ~()~. Its fields are not evaluated and
variables in the payload are not referenced by the generated program. This is
intended for hot compiler code where a runtime branch is still too expensive.

The static level should be passed through dune rather than read only with
~Sys.getenv~ inside the PPX. This makes the selected level part of dune's cache
key:

#+BEGIN_SRC lisp

(preprocess
 (pps delator.ppx -- --static-level=%{env:DELATOR_STATIC_LEVEL=trace}))

#+END_SRC

*** Level-Gated Values

Code which exists only to feed a particular log level can carry that level as
well. The PPX removes the value, its initializer, and every matching structural
slot when the level is disabled.

#+BEGIN_SRC ocaml

type request = {
  path : string;
  trace_context : context [@log_value.trace];
}

let handle
    (trace_context : context [@log_value.trace])
    path =
  let[@log_value.trace] detail =
    inspect (trace_context [@log_value.trace])
  in
  let request =
    {
      path;
      trace_context = (trace_context [@log_value.trace]);
    }
  in
  [%log.trace "request"
    ~detail:(context_field (detail [@log_value.trace]))];
  dispatch
    (request.trace_context [@log_value.trace])
    request.path

#+END_SRC

Use ~[@log_value.LEVEL]~, where ~LEVEL~ is ~trace~, ~debug~, ~info~, ~warn~,
or ~error~. The attribute may mark:

- a local or top-level nonrecursive binding;
- a function formal and its actual argument;
- a record field, construction field, projection, pattern field, or mutable
  field update value;
- a positional variant component, construction component, or pattern
  component; and
- an interface formal, field, component, or whole value declaration.

Levels form the availability lattice
~Trace < Debug < Info < Warn < Error~. A value declared at ~L~ may be used in a
context ~C~ iff ~C <= L~. Thus Info admits Info, Debug, and Trace uses, while
Trace admits only Trace. Declarations and uses are annotated explicitly;
structural slots such as formals and fields require exact levels so their
erasure remains coherent.

Checking precedes erasure. Instrumentation is a use at its configured level;
~[@delator.skip]~ and ~[@@delator.skip_all]~ remove those uses.

Because erasure changes function arity and aggregate layout, the static level
is part of the compilation-unit ABI. Compile every unit sharing such an
interface at the same level, passed through dune's ~pps~ arguments.

Recursive or grouped gated bindings are unsupported. Functions and records
must retain at least one ordinary formal or field, so erasure never collapses
the entire callable or record shape.

*** Low Boilerplate

Events are small expressions and functions may be instrumented with an
attribute. Fields which need conversion say how to convert themselves rather
than relying on runtime type inspection.

#+BEGIN_SRC ocaml

let lower (name [@delator.field Fun.id]) =
  [%log.debug "starting lowering" ~name];
  [%log.info "lowered node" ~node:(Delator.Field.int 42)]
[@@delator.instrument]

#+END_SRC

Instrumentation defaults to ~Debug~. It also supports
~[@@delator.level trace]~, ~[@@delator.skip_all]~, and
~[@@delator.no_exn_log]~. Parameters may use
~[@delator.field converter]~, ~[@delator.field.pp printer]~, or
~[@delator.skip]~. A parameter without a converter is represented as
~<opaque>~.

*** Multicore Coherence

Each domain writes eagerly into its own buffer. Closing a root span flushes the
domain chunk while holding one global sink mutex. A chunk is also flushed at
64 KiB and when its domain exits, so event-only child domains do not lose their
tail and a long-lived span cannot grow its buffer without a bound. Output from
different domains has no total ordering, but complete lines are never split or
interleaved.

Values are formatted when the event occurs. Deferring formatting until flush
would be incorrect for mutable compiler structures because the value could
change before it is rendered.

*** Performance

The dynamically disabled event path is one filter branch and zero allocation.
Target filtering has specialized paths for zero or one directive, which are
the common configurations.

On OxCaml, the instrumentation PPX emits ~stack_~ field and action closures and
~Delator.in_span~ accepts them at ~local~. This keeps them from escaping even
in opaque development builds. The stock OCaml implementation relies on release
cross-unit optimization to sink those closures into the enabled branch.

The renderer writes directly into a 4 KiB domain-local output chunk. Each
domain also owns one 21-byte decimal scratch area, large enough for the sign and
digits of every OCaml ~int~ and ~int64~. Small C ~noalloc~ stubs format numbers
directly into this area rather than allocating temporary strings. Integer
fields retain their numeric representation until the renderer reaches them;
they do not call ~string_of_int~ on the event path.

The ordinary ~in_span~ path keeps IDs and timestamps in reusable domain-local
arrays. They begin with room for 16 nested spans and double only when a domain
exceeds its previous maximum nesting depth. With timing disabled, an enabled
span through a no-op renderer has no steady-state allocation. The low-level
~Runtime.new_span~ API still allocates an abstract lifecycle object because
that object may escape its lexical span.

** Events

The event extensions are ~[%log.trace]~, ~[%log.debug]~, ~[%log.info]~,
~[%log.warn]~, and ~[%log.error]~. The ~[%delator.LEVEL]~ spelling is available
as an alias.

Messages must be string literals. A field pun such as =~name= is shorthand for
a string field. Other values use an explicit converter:

#+BEGIN_SRC ocaml

[%log.info "lowered node"
  ~name
  ~node:(Delator.Field.int node)
  ~typ:(Delator.Field.pp Type.pp typ)]

#+END_SRC

** Configuration

- ~DELATOR_LOG=lowering=trace,info~ sets target-prefix directives and the
  default filter. The longest matching target prefix wins.
- ~DELATOR_FORMAT=flat~ selects breadcrumb lines instead of the default span
  tree. ~DELATOR_FORMAT=json~ (or ~ndjson~) selects newline-delimited JSON when
  the optional ~yojson~ dependency was present while building Delator.
- ~DELATOR_COLOR=auto|always|never~ colors level labels and span markers. The
  default is ~auto~, which colors only a terminal, honors ~NO_COLOR~, and
  disables color for ~TERM=dumb~. ~1~ and ~0~ are aliases for ~always~ and
  ~never~.
- ~DELATOR_UNBUFFERED=1~ writes each complete line through immediately for
  crash diagnosis.
- ~DELATOR_CLOCK=monotonic|tsc|off~ selects span timing. ~monotonic~ is the
  portable default. ~tsc~ reads the processor timestamp counter after a
  one-time calibration and is accepted only when the CPU reports an invariant
  TSC; it is intended for lower-overhead approximate durations in logs. ~off~
  writes zero durations and skips clock reads and timestamp storage.
- ~DELATOR_STATIC_LEVEL~ controls PPX elision when it is passed through the
  dune stanza shown above.

Runtime levels, renderer, color, and clock should normally be configured before
spawning domains. The default level is a plain immediate reference. OCaml
permits a concurrent read to observe an older immediate value without tearing,
so later level changes propagate eventually rather than providing a
synchronization point. Do not change the clock source while spans are active.

The OxCaml interface asserts the documented runtime contract with
~Obj.magic_portable~, which is a ~%identity~ primitive and adds no runtime work
to an event or span. This permits direct calls and PPX-generated logging from
~portable~ worker closures. Configuration remains an initialize-before-spawn
operation, and low-level span values remain owned by the domain that created
them.

Color can also be changed after initialization with
~Delator.Color.set_enabled~.

*** NDJSON

Install Delator together with Yojson to enable the machine-readable renderer:

#+BEGIN_SRC sh

opam install delator yojson
DELATOR_FORMAT=json your-program

#+END_SRC

Opam records Yojson as an optional dependency, so installing or removing it
rebuilds Delator with the corresponding renderer selection. Without Yojson,
the tree and flat renderers have no JSON dependency; selecting ~json~ reports
that Delator must be rebuilt with Yojson.

The NDJSON stream contains one object per event, span start, or span end. Every
object has ~kind~, ~target~, ~span_id~, ~parent_span_id~, ~level~, ~message~,
and ~fields~ members. Span ends additionally contain ~duration_ns~. Missing
context is JSON ~null~, strings are escaped by Yojson, and integer and boolean
fields remain JSON numbers and booleans.

** OxCaml / OCaml Compatibility

Some source files have ~_ox~ and ~_stock~ variants. Dune selects one variant
from ~%{ocaml-config:version}~ before compilation.

The split exists in two places for two different reasons:

- ~delator_ox.ml~ and ~delator_ox.mli~ expose OxCaml's ~local~ closure modes.
  The stock parser does not understand that syntax.
- ~delator_ppx_rewriter_ox.ml~ handles OxCaml's unified function AST and emits
  mode annotations.
- ~delator_ppx_rewriter_stock.ml~ handles the older stable AST exposed by
  ppxlib before 0.36.
- ~delator_ppx_rewriter_unified_stock.ml~ handles ppxlib 0.36 and newer, whose
  function AST is unified but which does not contain OxCaml's mode
  constructors.
- The corresponding ~delator_log_value_*~ files isolate the same three AST
  boundaries for structural value erasure and level-flow checking.

Keeping these variants separate is less clever than hiding them behind another
source preprocessor and makes it clear which compatibility boundary is being
tested. The generated module name remains ~Delator~ / ~delator.ppx~ in either
build.

** Cost Model

A statically removed event is ~()~. A dynamically disabled event is
one filter branch and zero allocation.

An instrumented function which survives static elision still performs the
dynamic check. OxCaml stack-allocates the generated closures. On stock OCaml,
the release profile should be used if closure sinking matters.

Values used only for logging can use ~[@log_value.LEVEL]~ when their allocation,
initialization, aggregate slot, or function argument should disappear with that
level. Ordinary values placed directly in a removed event already disappear
without an additional annotation.

** Benchmarks

The native microbenchmark harness reports median latency and allocated words
per operation. Benchmarks must use the release profile when measuring inlining
decisions.

#+BEGIN_SRC sh

dune build --profile release bench/hot_paths.exe bench/static_elision.exe
_build/default/bench/static_elision.exe
_build/default/bench/hot_paths.exe is_enabled
_build/default/bench/hot_paths.exe ppx_disabled
DELATOR_LOG='lowering=trace,info' \
  _build/default/bench/hot_paths.exe is_enabled_directive
_build/default/bench/hot_paths.exe instrument_disabled
_build/default/bench/hot_paths.exe clock_monotonic
_build/default/bench/hot_paths.exe clock_tsc
_build/default/bench/hot_paths.exe span_enabled_monotonic
_build/default/bench/hot_paths.exe span_enabled_tsc

#+END_SRC

The cross-library harness pins ~ocaml-trace~ to commit
~13b7b6669e22a04c1c5c85cf422880873dec7180~, builds its ~trace.core~ package
with the active compiler, and compares disabled and enabled events and spans.
Most enabled workloads use no-op collectors on both sides. The primary
enabled-span workload instead gives ocaml-trace the same ID and
monotonic-timing work. No
workload serializes output. The first run needs ~git~ and network access; the
checkout and installation remain under ~_build/~.
It runs ~dune clean~ in the pinned ~ocaml-trace~ checkout before every build so
no result depends on a previously compiled competitor artifact.

#+BEGIN_SRC sh

nix develop ../verocaml --command \
  taskset -c 2 bench/compare-ocaml-trace disabled_event
nix develop ../verocaml --command \
  taskset -c 2 bench/compare-ocaml-trace enabled_event_field
nix develop ../verocaml --command \
  taskset -c 2 bench/compare-ocaml-trace enabled_span

#+END_SRC

Available workloads are ~disabled_event~, ~disabled_event_field~,
~disabled_span~, ~enabled_event~, ~enabled_event_field~, ~enabled_span~, and
~enabled_span_null~. The primary ~enabled_span~ comparison uses the same
monotonic clock for Delator and an ocaml-trace collector which assigns IDs and
records durations. ~enabled_span_null~ is only a dispatch-floor diagnostic: it
disables Delator's clock and gives ocaml-trace a collector which returns one
immediate token. It is not an equivalent-work library comparison. Set
~DELATOR_BENCH_ITERS~ to override the iteration count. Delator's static elision
has no ~ocaml-trace~ equivalent and remains in the separate
~static_elision.exe~ benchmark.

~tree_event~ exercises actual rendering and should be run with stderr redirected
to ~/dev/null~. ~tree_exit~ additionally exercises worst-case signed ~int~ and
~int64~ formatting.

The pinned measurements and rejected optimization experiments are recorded in
[[file:bench/RESULTS.org][bench/RESULTS.org]].
